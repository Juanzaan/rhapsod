## Summary

Autoplay as a channel DJ, playback that recovers from stalls and expiring URLs, measured search and autoplay quality, playback metrics for Prometheus, a hardened panel and deployment, a setup wizard that finishes an install, and a startup that systemd can restart. The audio filters are removed, which makes this a major release.

## Changes

### Removed

- The audio filters (`!bassboost`, `!nightcore`, `!vaporwave`, `!8d`, `!filter`, `!effects`) and their panel controls. They were rarely used and restarted the stream on every change. `!test-tone` and `!chart` remain as their own commands; a filter saved in `data/state.json` by an older version is ignored.

### Playback

- Autoplay works as a DJ that rotates similar tracks, channel classics (requested and finished before, rested six hours) and discoveries from the channel's favorite artists. Its own picks no longer count as requests in `!tops` or the taste profile, skipped picks rest their source for two turns, fetched mixes are reused for 30 minutes, and recent listening history seeds the rotation after a restart.
- A stream that stalls mid-song resumes at the position where it stopped with a freshly resolved URL; radio rejoins the live edge. 403 retries also resume where the audio stopped, retry silently and match the HTTP error wording.
- A prepared or cached audio URL is reused only when it stays valid for the whole track; a URL about to expire is resolved again before playback instead of failing mid-song.
- `!seek` and 403 retries count as the same play: no second "Reproduciendo" message, no extra stat, and `!previous` returns the prior track.
- Prewarmed next-track streams use the configured FFmpeg binary and User-Agent.
- Radio plays streams that refuse HEAD probes, pasted TuneIn links, and direct streams on ffprobe builds without `-max_redirects`. Apple Music links resolve through the keyless iTunes lookup; playlists expand like Spotify collections.

### Search and measurement

- Search ranking no longer lets short title words match longer query terms, counts a query term found in the channel name, and penalizes Spanish reaction videos and live or unplugged cuts unless asked for.
- `npm run eval:search` (51 cases, 100% accuracy floor in the test suite) and `npm run eval:autoplay` (repeats, artist spread, energy continuity, share of new tracks) measure ranking and autoplay offline.
- Per-track playback latency is logged (`startDelayMs`, `handoffGapMs`, `coldStart`, `prewarmed`), `scripts/log-stats.mjs` reports it, and the panel serves `GET /api/metrics` in Prometheus text format behind its basic auth and loopback bind.

### Chat

- `!help <command>` explains one command, and each `!help <n>` page names the next category.
- Optional vote skip with `RHAPSOD_VOTE_SKIP` (default `false`): more than half of the listeners in the bot's channel can skip another user's track.
- `!stop` and `!clear` follow the ownership rule of `!skip` and `!remove`; tracks of users who left the server are communal. `!channel-move` works while the bot cannot talk.
- Long messages are split instead of lost, split parts stay together, and outgoing messages are spaced one second apart.

### Panel

- Redesigned dashboard and pages with a shared animated background, motion controls, a server tree that includes empty channels in TeamSpeak order, and click-to-copy commands.
- The setup wizard finishes an install: it advances after a successful connection test, keeps earlier answers and saves only settings.
- Panel writes must be same-origin JSON, pages no longer embed the password, a published default password refuses to start, settings are validated with the startup rules, and binary paths are read-only from the web.

### Security

- Every ffmpeg and ffprobe connection goes through a local egress guard that refuses private addresses and plain HTTP, including redirects and HLS segments.
- `scripts/spotify-auth.mjs` listens on 127.0.0.1 only and verifies the OAuth `state`.
- Logs redact bearer tokens and cookie headers and no longer print raw stream URLs.

### Reliability and operations

- The event-loop watchdog runs every 15 seconds (`RHAPSOD_WATCHDOG_INTERVAL_SECONDS`).
- Startup exits with code 1 when the TeamSpeak server is unreachable, so `Restart=on-failure` restarts it; setup mode stops cleanly on SIGTERM.
- Every exit path flushes favorites, history, telemetry and the queue. Unreadable data files are kept as `<name>.corrupt-<time>`, every write is fsynced, and history and library saves are coalesced.
- The yt-dlp daemon no longer crashes on short links or hangs on stuck extractions, and yt-dlp timeouts are validated with the rest of the configuration.
- SoundCloud keeps the last discovered `client_id`, radio searches rotate across mirrors, and outbound requests send the running version as User-Agent.
- `scripts/deploy.sh` deploys with a wait for idle playback, a backup and automatic rollback. The installer supports aarch64 and verifies downloads, systemd units are sandboxed, and Docker runs as uid 1000.
- `npm run smoke` starts the built bot in setup mode and checks the panel; `src/main.ts` is split into tested modules under `src/bootstrap/`, commands are table-driven, chat texts live in `src/lib/messages.ts`, and the panel's browser code is linted and type-checked.
- `docs/privacy.md` documents what is stored per TeamSpeak user and how to delete it.

## Upgrade

This is a major release because it removes commands: `!bassboost`, `!nightcore`, `!vaporwave`, `!8d`, `!filter` and `!effects` now get the unknown-command reply. `!test-tone` and `!chart`, previously also reachable as `!effects test-tone` and `!effects chart`, remain as their own commands. A filter saved in `data/state.json` is ignored.

Node.js >=22.19.0 is required. Back up configuration and data, run `npm ci` and `npm run build`, and restart when `/api/state` reports `playerState: "idle"`. On hosts with `scripts/deploy.sh`, run `sudo bash scripts/deploy.sh --ref v4.0.0` instead.

If the panel uses a default password it will not start; set a unique `RHAPSOD_PANEL_PASSWORD` first. Existing installs keep the old `Requires=` line in `/etc/systemd/system/rhapsod.service` until the installer runs again: change it to `Wants=` and run `systemctl daemon-reload`.

Docker installs: run `sudo chown -R 1000:1000 data .env` before recreating the containers, which now run as uid 1000.

The watchdog now defaults to 15 seconds. An env file with `RHAPSOD_WATCHDOG_INTERVAL_MINUTES=15` keeps working and logs a deprecation warning; replace that line with `RHAPSOD_WATCHDOG_INTERVAL_SECONDS=15`, or set it to `0` to keep the watchdog off.

A yt-dlp timeout outside its range now stops startup. Before restarting, compare any `RHAPSOD_YTDLP_*_TIMEOUT_MS` line from `grep TIMEOUT_MS /etc/rhapsod.env` with the ranges in `.env.example`.

A bot that cannot reach TeamSpeak at startup now exits with code 1 instead of 0, so `Restart=on-failure` restarts it after `RestartSec`.

Docker Compose uses Linux host networking to keep the panel and daemon on localhost. Review the deployment guide before recreating containers. Existing data formats remain supported.

## Verification

Run `npm run check` and `npm run test:coverage`, then `npm run build && npm run smoke`. After deploying, confirm `/api/state` answers, play a track and a radio station, check that `!help`, `!skip` and autoplay behave as described, and that `GET /api/metrics` returns `rhapsod_build_info` with version 4.0.0. Test an idle restart before using favorites or stats, then confirm existing preferences and listening history remain available.
